# 知序：课程数据结构与批量导入

课程内容独立保存在 `src/seed.json`，界面在 `src/App.tsx`、`src/Editor.tsx`、`src/styles.css`；数据类型、验证、合并、Markdown 转换位于 `src/model.ts`，IndexedDB 事务位于 `src/db.ts`。后续整理课件只需生成 JSON，不需要修改界面。

## 1. 文件格式

```json
{"schemaVersion":1,"nodes":[]}
```

`nodes` 是扁平数组，通过 `parentId` 形成层级。完整结构可包含多个学期、课程、章节和知识点；也可以只导入少量知识点，它们的上级必须已存在于当前知识库，或出现在同一文件中。数组中上级与下级的顺序不限。

| level | 内容 | parentId |
| --- | --- | --- |
| 0 | 学期 | 必须为 null |
| 1 | 课程 | 所属学期的 id |
| 2 | 章节 | 所属课程的 id |
| 3 | 知识点 | 所属章节的 id |

## 2. 所有内容的公共字段

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| id | string | 必填，整个知识库内唯一；字母、数字、下划线、短横线，最多120字符。建议按课程和章节编制稳定ID。 |
| parentId | string 或 null | 必填。学期为 null，其他内容指向上一级。 |
| level | integer | 必填，0、1、2、3之一。 |
| title | string | 必填，1至100字符。 |
| description | string | 可选，最多600字符，默认为空。 |
| color | string | 可选，六位十六进制颜色，默认 #d5e8f1。 |
| order | number | 可选，同一上级中的排序值，较小的在前，默认0。 |
| createdAt / updatedAt | number | 可选，毫秒时间戳，导入时默认当前时间。 |
| sample | boolean | 可选，是否显示示例标记，默认false。 |

## 3. 知识点的额外字段（level = 3）

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| kind | string | 概念、定理、模型、方法、理解或笔记等标签。 |
| body | string | Markdown正文，定理与一般形式；支持 `$...$` 和 `$$...$$` 公式。 |
| examples | array | 例题列表，默认为空，最多100题。 |
| sourceFile | string | 来源文件名或资料名称，最多500字符；只保存文字，不会上传或读取原文件。 |
| sourcePage | string | 页码或页码范围，例如 `12`、`12–14`，最多100字符。使用字符串以保留罗马数字等标记。 |
| supplement | string | 补充说明，支持Markdown与公式；可以记录老师的补充、整理疑问和自注。 |
| source | string | 可选的 http/https 参考资料链接。 |

每道例题：`{"id":"唯一编号","title":"例题标题","prompt":"Markdown题目","solution":"Markdown解答"}`。`id` 可省略自动生成；正文、题目、解答和补充说明各不超过100000字符。

## 4. 导入与更新规则

1. 在“导入与备份”中选择「合并导入 JSON」或「更新知识点 JSON」，导入前显示新增数、保留数，更新模式还显示实际变化的知识点数量。
2. 「合并导入 JSON」：新 ID 加入知识库；已有相同 ID 保留原记录全部内容，新子节点仍然可以加入该上级。「更新知识点 JSON」：新 ID 同样加入；已有相同 ID 的知识点（level=3）用文件中的完整记录覆盖，包括标题、正文、例题、来源、备注和显示属性。同编号的学期、课程、章节不被覆盖；文件里没有的记录也不会删除。
3. 同一文件内重复 ID、缺失上级、上级类型错误、已有 ID 对应不同层级/上级，都会拒绝整批导入。错误不会导致部分内容已写入。
4. 覆盖更新按稳定 ID 匹配，不按标题匹配。它不是局部补丁：例题列表整体替换，省略的可选字段按默认值清空。更新文件应带上想保留的完整知识点内容。保留原创建时间，修改时间记为本次更新时间；只有文件时间戳不同而内容完全相同时，不重复更新。
5. 确认后在一个 IndexedDB 事务中重新检查数据并写入；错误会整批回滚。有实际覆盖时，在同一事务中保存更新前的整库备份，可从「下载上次更新知识点前的备份」获取。只保留最近一次实际更新前的备份；普通合并、无变化的重复导入不会替换它。
6. 完整备份也可以选择合并，以保留当前内容。另有“恢复完整备份”功能：独立检查文件内完整的层级，在确认后用备份替换整个本地知识库，操作前可先导出当前备份。自动备份文件也可通过该入口恢复。
7. JSON 文件最大 10MB，单批最多 10000 条。未知字段不会自动保留，请使用本文档中的字段。更新模式不支持改变原记录的层级或上级；移动知识点请另外处理。

示例：`examples/course-batch.json` 是自带完整上级结构的文件；`examples/knowledge-points-batch.json` 演示向内置“模型与估计”章节添加知识点。

## 5. Markdown导入与导出

进入一个章节，选择“导入 Markdown”。一份 `.md` 文件创建一个知识点，导入后先进入编辑预览，点击保存才写入。文件最大1MB。

- 开头第一个非空行若为 `# 标题`，作为知识点标题；否则使用文件名。
- 紧随标题的首个引用行 `> 简介` 可作为简要说明。
- 普通正文归入“定理与一般形式”。
- `## 例题 1：标题` 开始一道例题；`### 解答` 以下为其解答；可重复。
- `## 来源` 下支持 `来源文件：...`、`页码：...`。
- `## 补充说明` 以下为补充说明。其他普通Markdown标题保留在正文中。
- 代码围栏中的这些标题保留为代码，不作为分段标记。
- 缺少来源文件字段时，记为导入文件名。
- 网页中不执行原始HTML；危险链接协议被过滤。图片以说明文字显示，避免相对图片路径失效。
- Markdown不是完整LaTeX文档：不处理 documentclass、usepackage、外部tex文件。

## 6. 存储与隐私

### 知识点关联

完整 JSON 备份可额外包含 `links` 数组，旧文件可以省略。关联独立于知识点正文，更新知识点内容不会删除已有关系。

```json
{"schemaVersion":1,"nodes":[],"links":[{"fromId":"topic-a","toId":"topic-b","note":"同一个思想的不同表达"}]}
```

以上为关联字段示意；合并时这两个知识点必须已存在，或一并放在文件的 `nodes` 数组中。完整恢复时，两端必须存在于文件内部。

- 关联是双向的，两端只能是不同的知识点（level=3），可以跨课程。每对知识点最多一条关联，反向也算同一条。
- `note` 是可选的纯文字说明，最多600字。`createdAt`、`updatedAt` 为可选毫秒时间戳；`id` 由程序根据两端编号生成，无需手动填写。
- 合并导入与更新知识点模式只添加新关联，保留已有相同关系的说明。修改说明或移除关联请在知识点页面操作。
- 完整备份及知识点更新前的自动备份都包含关联。恢复备份会替换全部关联；没有 `links` 的旧文件恢复后关联为空。普通合并或内容更新省略 `links` 时，不会清除已有关系。
- 单批最多20000条关联。非法目标、自关联、文件内重复关联会拒绝整批导入。删除内容时，涉及被删知识点的关联一起清理，另一端笔记保留。

网站程序可以公开部署，内容存在访问者当前浏览器的 IndexedDB。不同浏览器、设备和站点地址的存储相互独立；本地预览网址与 GitHub Pages 网址也各有自己的数据。更换设备、网址或清除浏览器数据前，请导出JSON备份。网站没有账户、上传接口或AI服务，不自动同步到GitHub。

## 7. 示例计算核查

内置最小二乘示例：(1,2)、(2,3)、(3,5)。均值为 x̄=2、ȳ=10/3，Sxx=2、Sxy=3，故斜率3/2、截距1/3；残差1/6、−1/3、1/6，SSE=1/6。对应数值测试见 `tests/model.test.tsx`。

参考：Penn State STAT 501，Simple Linear Regression，https://online.stat.psu.edu/stat501/Lesson01 。题目为自拟教学示例，不代表用户真实课程大纲。
